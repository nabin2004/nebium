\subsubsection{Critical Appraisal: PyTorch and GGUF vs. Legacy Pipelines}
\label{sec:tools_deployment}
While early neural game engines relied on TensorFlow or Keras for static graph execution, modern workflows use PyTorch~2.3 \parencite{paszke2019pytorch}. Declarative graph execution in TensorFlow complicates debugging by obscuring dynamic tensor shapes during autoregressive decoding. In contrast, PyTorch couples imperative debugging with TorchDynamo kernel fusion. PyTorch~2.3 natively integrates scaled dot-product attention, dispatching to fused FlashAttention-2 kernels that remove quadratic $\mathcal{O}(T^2)$ memory bandwidth bottlenecks.

For edge deployment, single-file GGUF binaries \parencite{gerganov2023llamacpp} replace legacy ONNX runtimes \parencite{bai2019onnx}. ONNX pipelines decouple model weights from tokenizers and configs, creating dependency overhead and Python GIL bottlenecks during sequential generation. GGUF packages tensor parameters, quantization scales, and BPE vocabularies into a single binary. Using POSIX zero-copy memory mapping (\texttt{mmap}), GGUF operates without a Python runtime. Block-wise $k$-quantization (\texttt{Q4\_K\_M}) compresses the Nebium-Small checkpoint to 88.1~MB (and Nebium-Large FP16 to 1.43~GB), surpassing multi-file ONNX runtimes in deployment portability and operational simplicity.
