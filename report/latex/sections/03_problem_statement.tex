\subsection{Deep Learning Problem Formulation}
\label{sec:dl_problem}
\begin{figure}[H]
  \centering
  \includegraphics[width=0.82\linewidth]{figures/next_move_modelling.pdf}
  \caption[Autoregressive Next-Move Modeling]{Autoregressive move prediction in chess. Given a sequence of prior plies, the causal decoder models the conditional probability of the next coordinate token without looking ahead.}
  \label{fig:ml_problem}
\end{figure}

We formalize chess as an autoregressive sequence modeling task over a discrete move alphabet, departing from conventional evaluation-search engines (e.g., minimax $\alpha$-$\beta$ pruning or MCTS). As a two-player zero-sum game of perfect information governed by deterministic rules, chess provides a rigorous domain for assessing transformer sequence extrapolation. A match $G$ of length $T$ plies is expressed as an ordered token sequence:
\begin{equation}
    \mathbf{x} = \left( x_1, x_2, \dots, x_T \right), \quad x_t \in \mathcal{V}
\end{equation}
where $\mathcal{V}$ is a finite vocabulary. The neural network parameterized by $\theta$ learns the joint probability distribution $P_\theta(\mathbf{x})$ factorized causally via the chain rule:
\begin{equation}
    P_\theta(\mathbf{x}) = \prod_{t=1}^T P_\theta(x_t \mid x_{<t})
\end{equation}
Parameters $\theta$ are optimized by minimizing expected cross-entropy loss over corpus $\mathcal{D}$:
\begin{equation}
    \mathcal{L}_{\text{CE}}(\theta) = - \mathbb{E}_{\mathbf{x} \sim \mathcal{D}} \left[ \frac{1}{T} \sum_{t=1}^T \log P_\theta(x_t \mid x_{<t}) \right]
\end{equation}
As shown in Figure~\ref{fig:ml_problem}, the model conditions strictly on earlier plies ($x_{<t}$), learning board state transitions from history alone.

This formulation introduces three core representation challenges:
\begin{enumerate}
    \item \textbf{Absence of Spatial Inductive Bias}: The transformer receives no architectural priors regarding 2D grid topology, piece trajectories, or special constraints (castling, en passant, promotion).
    \item \textbf{Latent State Maintenance}: Because moves denote coordinate displacements rather than full board tensors, the network must internally track piece positions and pins over extended horizons.
    \item \textbf{Severe Action Sparsity}: At ply $t$, legal actions $\mathcal{A}_{\text{legal}}(s_t) \subset \mathcal{V}$ comprise an average of only 30--40 moves out of thousands of vocabulary permutations, leaving unconstrained sampling vulnerable to illegality.
\end{enumerate}

\label{sec:dataset_char}

\subsubsection{Data Filtering and Cleaning Pipeline}
Raw PGN files exhibit variable player expertise and clock aborts. An automated pipeline (\texttt{src/data/prepare.py}) applied four filtration criteria:
\begin{itemize}
    \item Retained standard games (\texttt{Variant "Standard"}), excluding Chess960 and non-standard variants.
    \item Discarded matches terminating in $<10$ plies; games exceeding 256 plies were truncated to the context limit.
    \item Retained games where both players maintained an Elo rating $\ge 1500$, removing low-rated noise.
    \item Discarded non-sequential metadata tags, isolating pure move strings terminated by match outcomes (\texttt{1-0}, \texttt{0-1}, \texttt{1/2-1/2}).
\end{itemize}
The resulting 208,412 games are partitioned into \textbf{training} (85\%, 177,150 games), \textbf{validation} (10\%, 20,841 games), and \textbf{test} sets (5\%, 10,421 games).

\subsection{Move Representation and Tokenization Strategy}
\label{sec:move_rep}
Standard Algebraic Notation (SAN) such as \texttt{Nxf7+} is human-readable format but introduces linguistic ambiguity (e.g., disambiguation prefixes like \texttt{Nbd7}). To eliminate ambiguity, Nebium standardizes games into the \textbf{Universal Chess Interface (UCI)} coordinate format, where each move specifies Cartesian origin and destination squares:
\begin{equation}
    \label{eq:uci_format}
    m = \langle \text{file}_1, \text{rank}_1, \text{file}_2, \text{rank}_2, [\text{promotion}] \rangle \in \{\texttt{a1}\dots\texttt{h8}\} \times \{\texttt{a1}\dots\texttt{h8}\} \times \{\epsilon, \texttt{q}, \texttt{r}, \texttt{b}, \texttt{n}\}
\end{equation}
For example, moving a pawn from e2 to e4 is uniquely encoded as \texttt{e2e4}, kingside castling as \texttt{e1g1}, and queen promotion as \texttt{e7e8q}.

\subsubsection{Byte-Pair Encoding (BPE) Tokenization}
Tokenization directly influences transformer efficiency. Character tokenization quadruples sequence lengths, diluting attention over extended plies \parencite{stockl-2021-watching}, while naive word indexing lacks sub-coordinate compositionality. We trained a domain BPE tokenizer (\texttt{ChessTokenizerHF}, Figure~\ref{fig:tokenizer}) starting from 83 base ASCII characters and sub-units. Under whitespace pre-tokenization, BPE merges character pairs into complete UCI move strings. Because whitespace bounds each move, the vocabulary exhausts once all 1,968 distinct tournament moves in the corpus are merged, producing a domain vocabulary of $V = 2,056$ tokens with five control tokens:
\begin{equation}
    \mathcal{V}_{\text{special}} = \left\{ [\texttt{PAD}], [\texttt{UNK}], [\texttt{BOS}], [\texttt{EOS}], [\texttt{SEP}] \right\}
\end{equation}
This preserves 1:1 token-to-move alignment across the autoregressive horizon without sequence dilution.
