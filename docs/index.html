Abstract

Chess Without Minimax: Pure Language Modeling of the 64 Squares

Classical chess engines (Stockfish, Komodo) rely on alpha-beta tree search over handcrafted position evaluations, while reinforcement learning agents (AlphaZero, Leela Chess Zero) employ Monte Carlo Tree Search (MCTS) guided by dual value-policy networks. Both approaches mandate hardcoded board state trackers, legal move generators, and game-specific simulation steps.

In this work, we present Nebium: a causal Transformer architecture that treats chess games purely as text streams of space-delimited UCI move tokens. Without knowledge of board geometry, piece rules, or turn order, Nebium internalizes the game solely by minimizing autoregressive cross-entropy loss over 245,293 standard rated games from the Lichess public database. Equipped with Rotary Positional Embeddings (RoPE), SwiGLU feed-forward networks, RMSNorm, and domain BPE tokenization, Nebium demonstrates that legal moves, opening book memory, tactical pins, and endgame conversions naturally emerge from self-supervised sequence prediction.

Key Highlights

Core Architectural & Engineering Contributions

1. Causal Sequence Formulation

Replaces complex 8×8 bitboard inputs with space-separated UCI strings (e.g. e2e4 e7e5 g1f3). A tailored 5,000-vocabulary BPE tokenizer packages games into 512-token contexts with minimal padding overhead.

2. Modern Transformer Backbone

Incorporates Rotary Position Embeddings (RoPE) to model relative move intervals, SwiGLU gating for non-linear expressivity, and Pre-RMSNorm for numerically stable FP16 training on modern GPUs.

3. Kaggle & WandB Integration

First-class Kaggle runtime automation: auto-resolves WandB and Hugging Face secrets, evaluates move legality after every epoch, and live-streams sample generation tables directly to WandB.

4. Universal GGUF Deployment

Native GGUF v3 exporter writes zero-dependency binary models (FP16/FP32). Enables instantaneous local inference and quantization through llama.cpp and lightweight C/C++ runtimes.

Architecture

Nebium Pipeline & Training Workflow

The complete end-to-end training and deployment pipeline, from compressed PGN dumps to local GGUF binaries:

Figure 2. Nebium System Architecture: Raw Lichess dumps are stream-decompressed, filtered for length, and converted to canonical UCI format. Sequences are tokenized by our chess BPE model, encoded via RoPE attention, passed through 6 stacked SwiGLU Transformer blocks, and exported to PyTorch and GGUF formats.
Stage 1

Data Curation

Streams .pgn.zst archives on the fly without RAM decompression spikes. Filters out games with fewer than 20 moves, retaining over 220,000 high-quality competitive matches.

Stage 2

Tokenization & RoPE

A BPE tokenizer identifies recurring opening combinations. Rotary Position Embeddings inject relative distance between moves directly into query and key projections.

Stage 3

Transformer Blocks

Pre-RMSNorm stabilizes gradients during half-precision training. The SwiGLU feed-forward layer captures intricate non-linear board interactions and piece defense chains.

Stage 4

Artifact Hub

Seamlessly pushes checkpoints, model cards, and tokenizer files to Hugging Face Hub, and outputs optimized GGUF binaries for edge deployment.

Local Deployment

Zero-Dependency GGUF Export & CLI Inference

Nebium features built-in export to GGUF format, enabling instant CPU/GPU execution without heavy deep learning frameworks:

# 1. Export trained checkpoint to FP16 GGUF python scripts/export_gguf.py --checkpoint outputs/best_model.pt --output nebium.gguf --precision fp16 # 2. Run generation CLI python scripts/generate.py --checkpoint outputs/best_model.pt --prompt "e2e4 c7c5" --max_moves 20
